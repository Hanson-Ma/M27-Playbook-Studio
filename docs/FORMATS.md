# Data contract: web editor ⇄ game tools

The web editor (`app/`) only reads and writes files in this repo. Everything that touches Madden 27 runs on the game PC
through `tools/export.ps1`. If the editor writes these files correctly, the game side builds them.

```
                 (any machine)                          │             (game PC)
 data/library/*.json  ──read──▶  app/  ──write──▶  playbooks/*.json        ──▶ tools/export.ps1 ──▶ build/PBOOKOFF-<NAME>  → Documents\Madden NFL 27\saves
 (game play library,                                playbooks/plays/*.json  ──▶                  ──▶ mods/pbstudio.fbmod   → MMC Mod Manager
  regenerated by PlayDump library)                  playbooks/sets/*.json   (planned, §5)
                                                    app-data/*.json (editor-only: concepts, tags, notes)
```

## Coordinates and units (shared by everything)
- Field coordinates are in **yards relative to the ball**. `x` is lateral, with **+x toward the offense's right**. `y` is depth, with **-y into the offensive backfield** (the LOS is y=0). QB under center is about (0,-1.4); a pistol QB about (0,-4); a shotgun QB about (0,-6).
- The OL is at x = -3.333, -1.666, 0, 1.666, 3.333 with y about -0.6 to -1.2. On-line receivers are at y about -0.8; off-line receivers at y about -2.2.
- Field: 53.33 yd wide. NFL hashes are 18.5 ft apart (x = ±3.08 from the middle of the field). The ball is spotted on a hash or in the middle; the editor should let you pick the spot for visualization only.
- Angles are in **degrees**: 0 = toward +x (right), 90 = straight upfield, 180 = toward -x (left), 270 = straight back. They're absolute, not relative to the player.
- `distance` is in yards; `speed` is 0–100.
- **Player slots**: a play's `assignments[i]` belongs to the player in slot `i` of its set's `movements.Normal[i]`. The order is fixed by the set, usually 0 QB, 1 HB/RB, 2–5 skill players, 6–10 LT LG C RG RT. Always look up by index; don't assume positions.
- **Read progression** (`reads[].pos`) and `vip` refer to slot numbers (1–5 are the eligible non-QB skill slots).

## 1. `data/library/` — read-only game data (export with `PlayDump library data/library`)
| file | shape |
|---|---|
| `formations.json` | `[{formId, name, type, asset}]` |
| `sets.json` | `[{setId, name, asset, formation (asset), classification, setType, canFlip, movements: {Normal: [Position], M1left: [...], ...}}]`, where `Position = {pos, depth, x, y, facing, stance, group, motionMan}`. `Normal` is the base alignment; the other keys (`M1left`, `M1right`, … `M5right`, `SM1left`…) are the set's **pre-snap motion presets**: the full 11-player alignment after that motion. |
| `plays.json` | `[{playId, name, asset, set (asset), offensePlayType, defensePlayType, blocking (asset), runHole, vip, allowHotRoutes, canFlip, global, assignments: [assignmentAsset per slot], reads: [{pos, pct, concept, combo}]}]`. `vip` = slot of the primary receiver (the **red** route). `global` = usable by custom playbooks without the mod (see "Availability"). |
| `assignments.json` | `{ "<asset>": {id, routeType, steps: [Step]} }`, where `Step = {type, ...fields}`. 5,402 reusable assignments; `routeType` (e.g. `AssignRouteType_RR_Slant`) is a good category for a route picker. |
| `enums.json` | `{fields: {"ReceiverCut.cutType": "ReceiverCutAngle", "AutomotionWaypoint.locoStyle": "AutomotionLocoStyle", …}, enums: {EnumName: [values…]}}`. Every legal enum value for play, set and step fields; build dropdowns from it. |

Names repeat across folders (several sets are called "Normal", and a minigame formation is also called "Shotgun"). **Identify things by `asset` or by id, never by display name alone.**

### Step types (assignment chain vocabulary)
Each player runs their steps in order. Every chain ends with `None`, which is added automatically when authoring.
| type | fields | meaning |
|---|---|---|
| `RunRoute` | distance, direction, speed | one route leg (pass routes) |
| `MoveDirection` | distance, direction, speed | non-route movement (screens, leads, QB paths) |
| `ReceiveHandoff` | distance, direction, speed | ballcarrier path through the mesh |
| `ReceiverCut` | direction (`RECEIVER_CUT_DIR_LEFT/RIGHT`), cutType (`ReceiverCutAngle`) | the cut animation between legs; doesn't move the player |
| `RunRouteFakeOut` | fakeout (`RunRouteFakeOutType`) | double-move fake |
| `GetOpen` | — | find space at the route's end (sit or settle) |
| `Delay` | time | wait (seconds) |
| `PassBlock` | time, flags | pass protect (`PassBlockFlags_ProtectReceiver` = screen blocking; `time` = block then release) |
| `RunBlock` | stalkDistance, slamDuration, time, flags, receiverBlockType | run block (the blocking scheme picks the target) |
| `LeadBlock` | blockingTechnique (`BLOCKINGTECHNIQUE_*`), blockingGap (`A_GAP_RIGHT … RUN_HOLE`) | lead, kickout, trap, wham, stalk or crack block |
| `InitialAnim` | anim (`InitialMoveType`: `MOVETYPE_WRSTART`, `_WRSTART_QUICK`, `_COUNTER_PULL`, `_POWER_PULL`, `_SKIP_PULL`, `_TRAP_PULL`, `_SCREEN_PULL`, `_BACKSTEP`, `_HOPSTEP`, `_COUNTERSTEP`, …), direction | opening step: releases, pulls, backfield steps |
| `QBScramble` | dropBackType (`DROP_TYPEENUM_QBDROP_*`), direction, distance | QB drop or rollout |
| `CannedHandoff`, `HandOffTurn`, `HandOffGive`, `HandoffFake`, `OptionHandoff`, `PitchBall`… | … | handoff / fake / read mechanics: **paired between QB and ballcarrier** |
| `AutoMotion` | waypoints [{position {x,y}, speed, facingAngle, locoStyle, shouldFaceEndPoint, transitID}], startEvent, startDelay, endDelay, stanceAtTarget | scripted motion. Waypoints are **absolute** field positions. |
| `OverrideFormPos` | stance, offsetX, offsetY | play-specific realignment of one player (e.g. X to a tight split) |
| `ManCoverage`, `HookZone`, `DeepZone`, `FlatZone`, `CurlFlatZone`, `PassRush`, … | … | defense |

**Play art is generated by the game from these steps.** To draw a route: start at the player's alignment (after `OverrideFormPos` and motion), then add each `RunRoute`/`MoveDirection`/`ReceiveHandoff` leg as a vector (`distance` at `direction`). `ReceiverCut` marks the corner; `GetOpen` and `Delay` end or pause the path.

## 2. `playbooks/<name>.json` — a custom playbook (becomes a save file)
```jsonc
{
  "name": "STUDIO",               // save file becomes PBOOKOFF-STUDIO (PBOOKDEF- for defense); A–Z0–9 only
  "side": "offense",
  "notes": "free text",
  "formations": [
    { "formation": "Shotgun", "sets": [
      { "set": "Y Trips Wk", "plays": [
        { "play": "PBS GT Counter", "audible": 2, "cpu": { "FirstDown": 40, "3rdAndShort": 30 } },
        { "play": "Inside Zone" }
      ]}
    ]},
    { "formation": "Special", "sets": "template" }   // copy this formation's sets/plays from the template save
  ]
}
```
- `formation` and `set` are display names. The set is resolved inside the formation's folder; `play` is resolved inside that set. A play can be any library play or any custom play from `playbooks/plays/`.
- `audible`: 1–4, at most one play per slot in a set. The game shows them in the audible menu as 1–4. (Stored as Flag bits 2/4/16/8; the builder handles that.)
- `cpu`: CPU play-call weights by situation (0–100). Allowed keys: `FieldGoal 3rdAndShort StopClock GoalLine RedZone Insidefive 2ndAndLong 3rdAndMedium 3rdAndLong Punt ConserveTime FakePunt FakeFieldGoal WasteTime Kneel Kickoff KickoffOnside 2ndAndMedium KickoffSafety PuntMaxProtect 2ndAndShort Hailmary GoalLinePass SignaturePlays ConserveTimeSafe RedZoneFringe RedZone_16_to_20 RedZone_11_to_15 RedZone_6_to_10 StopClockUser StopClockFakeUser 4thAndShort 4thAndMedium 4thAndLong GoFor2 FirstDown Squib Playaction GoFor1 RedZone_3_to_5 3RDExtraLong 4THExtraLong SuddenChange LastPlay`.
- **Keep special teams.** Include `Special`, `Kickoff` and `Safety Kickoff` (and usually `Goal Line Offense`), as `"template"` or explicitly.
- Capacity limits per save: **750 plays, 40 formations, 75 sets, 2200 CPU-weight rows**.

## 3. `playbooks/plays/*.json` — custom plays (become `mods/pbstudio.fbmod`)
All files in this folder are merged into **one** mod, because every play mod edits the shared GlobalPlaySheet.
```jsonc
{ "plays": [
  {
    "name": "PBS Snag",                     // in-game name; unique within its set
    "asset": "PBS_Snag",                    // asset leaf name; unique within the set folder, [A-Za-z0-9_]
    "base": "<asset of an existing play IN THE SAME SET>",   // supplies alignment, handoff/protection mechanics, flags, reads
    "playType": "OffensePlayType_PassShotgun",               // optional; defaults to base's
    "blocking": "BTCounter",                 // optional blocking scheme asset leaf (run plays)
    "runHole": 4,                            // optional
    "vip": 4,                                // optional: slot of the primary receiver (red route)
    "players": {                             // only slots you change; others keep the base play's assignment
      "3": "RunRoute/WR_Run90for30",         // reuse an existing assignment (path under .../Assignments/)
      "2": { "new": "PBS_Slot_Corner7",      // author a new assignment (asset leaf under Assignments/PBS/; reused if the name repeats)
             "routeType": "AssignRouteType_RR_Corner_Middle",
             "template": "RunRoute/...",     // optional source to copy; default = the base play's assignment for this slot
             "keep": 0,                      // keep the first N steps of the template (1 = keep an AutoMotion, 2 = keep a handoff precan)
             "steps": [ { "type": "RunRoute", "distance": 7, "direction": 90, "speed": 100 },
                        { "type": "ReceiverCut", "direction": "RECEIVER_CUT_DIR_RIGHT", "cutType": "RECEIVER_CUT_ANGLE_45" },
                        { "type": "RunRoute", "distance": 22, "direction": 45, "speed": 100 },
                        { "type": "GetOpen" } ] }
    },
    "reads": [ { "pos": 5, "pct": 0.8, "combo": 1, "concept": "Concept_Invalid" } ]   // optional; replaces the base's reads
  }
]}
```
Rules the editor must enforce:
- **The base play must come from the same set** as the new play. A play can't change its set, and handoff/pull mechanics depend on alignment.
- **Handoffs, fakes, options and pitches** (`CannedHandoff…`) must stay paired between the QB and the ballcarrier. Change them only by choosing a different base play, or with `keep` on both slots.
- Step `type` and enum values must exist in `enums.json`.
- Editing an existing game play in place is not supported yet. Clone it as a new play instead.
- **Route legs:** each `RunRoute` leg starts where the previous one ended. Use `speed` per leg (e.g. 80 on a stem, 100 after the break). Put a `ReceiverCut` between legs for the cut animation.
- **Releases** are the first leg(s), e.g. a 1–2 yd leg angled inside (95–110° for a left-side player) or outside, optionally preceded by `InitialAnim` `MOVETYPE_WRSTART`/`_WRSTART_QUICK`.
- **Double moves** use cut types such as `RECEIVER_CUT_ANGLE_STUTTER`, `_STUTTER_STREAK`, `_SLANT_AND_GO`, `_HITCH_GO_INSIDE/OUTSIDE`, `_OUT_AND_UP`, `_STICKNOD` or `_ZIG`, or a `RunRouteFakeOut` step.
- **Motion:** `AutoMotion` with startEvent `AUTOMOTIONSTARTEVENT_SNAP` gives jet/orbit-style snap motion. Waypoints are absolute positions, each with its own `speed` and `locoStyle` (`AUTOMOTIONLOCOSTYLE_NORMAL` = run, `AUTOMOTIONLOCOSTYLE_STRAFE` = shuffle). An orbit is several waypoints arcing behind the QB. The route continues from the last waypoint.

## Availability: which plays a custom playbook can use
- A custom playbook save only shows plays that are in the game's **global play sheet** (`plays.json` → `global: true`, 9,343 of 11,055). The game silently drops others; Gun Bunch "Mesh" vanished in testing.
- Non-global plays still work: `tools/export.ps1` detects them, and the mod pulls them into the global play sheet automatically, so they work once `pbstudio.fbmod` is enabled. The editor should badge them "needs mod".
- Custom plays (§3) always need the mod.

## Verified in-game behavior (lessons)
- **Play art is generated from the assignment steps.** There's nothing separate to draw.
- **Red route = `vip`** (the primary receiver's slot). Stock plays have exactly one red route. Plays whose `reads` were rewritten (all `combo` 0, `Concept_Invalid`) showed several red routes, and the exact rule is still being tested (`playbooks/plays/art-test.json`). Until it's settled, keep the base play's `reads` unless the user edits them, and set `vip` explicitly when the primary changes. Motion routes draw light blue.
- **In-game list order:** the Formation tab sorts by usage (GOTO%), and play order inside a set didn't follow the file order in testing. Store the user's order anyway; it's their intent.
- **New plays must be built from a base play in the same set.** Lock the handoff/fake/option slots in the editor unless the base is swapped.
- **Bundles and dependencies** are handled game-side (missing ones crash the game on load). The editor doesn't need to care.
- Game patches can change data. After a patch, the game PC regenerates `data/library` and the editor should reload it.

## 4. `app-data/` — editor-only state (the game never sees it)
For example, `app-data/concepts.json` (user-defined pass/run concept categories and which plays carry which tags) and per-play notes.
The editor owns this format. Seed it from `plays.json` → `offensePlayType`, `reads[].concept`, and `assignments.json` → `routeType`.

## 5. `playbooks/sets/*.json` — custom formations and sets (PLANNED: game-side builder not written yet)
The editor may write these now. The game PC will gain support, and until then `export.ps1` ignores the folder.
```jsonc
{ "sets": [
    {
      "name": "Trips Stack Wk",                 // in-game set name
      "asset": "PBS_Trips_Stack_Wk",            // leaf name
      "base": "<asset of an existing Set>",      // cloned: personnel packages, flags, slot order
      "formation": "<asset of an existing Formation, or the asset of a new one below>",
      "positions": [ { "slot": 2, "x": 7.5, "y": -1.2, "stance": "StanceType_2pt", "facing": 90 } ],  // changed slots only
      "movements": { "M1left": [ { "slot": 4, "x": 3.0, "y": -2.2 } ] },     // pre-snap motion presets (optional)
      "plays": [ { "from": "<play asset in the base set>", "name": "Snag", "asset": "PBS_TSW_Snag" } ]  // plays cloned into the new set
    }
  ],
  "formations": [ { "name": "Gun Stack", "asset": "PBS_Gun_Stack", "base": "<Formation asset>" } ] }
```
Rules:
- 11 players, with 7 on the line of scrimmage (y about -0.6 to -1.4).
- The OL keeps its spacing (±1.666 and ±3.333 around the center).
- The QB/HB stay in the base's depth class (under center / pistol / shotgun) so handoff animations stay valid.
- Plays cloned into a custom set keep their handoff mechanics, so only move players whose assignments don't depend on alignment (receivers), or rebuild those plays' assignments.
